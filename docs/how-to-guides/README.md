# How-to Guides

**Task-oriented documentation**

## Purpose

How-to guides are directions that guide the reader through solving a real-world problem. They are **task-oriented** and assume the reader already has basic knowledge and wants to accomplish a specific goal.

## What Belongs Here

### ✅ Include:
- **Practical steps** to solve a specific problem
- **Real-world scenarios** - "How to configure X for production"
- **Multiple approaches** when relevant (with pros/cons)
- **Troubleshooting tips** for common issues
- **Conditional logic** - "If X, then do Y"
- **Links to reference** for detailed parameters
- **Assumptions** about reader's skill level

### ❌ Don't Include:
- Teaching basic concepts (save for [Tutorials](../tutorials/))
- Complete learning paths (save for [Tutorials](../tutorials/))
- Exhaustive API listings (save for [Reference](../reference/))
- Deep theory and background (save for [Explanation](../explanation/))

## Writing Guidelines

1. **Name the goal clearly** - "How to deploy to production"
2. **Assume competence** - The reader knows the basics
3. **Focus on results** - Get the job done efficiently
4. **Be flexible** - Acknowledge different ways to achieve the goal
5. **Address common obstacles** - Help readers get unstuck
6. **Link to reference** - Don't duplicate detailed specs
